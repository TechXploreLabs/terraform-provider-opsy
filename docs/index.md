# Opsy Provider

The Opsy provider turns any API, CLI or script into Terraform objects without writing a new provider. You describe each operation as a **stack** in a YAML file, and the provider runs those stacks with the [seristack](https://seristack.getsaas.in/) package.

Stacks can run:

- **locally**, inside the provider process, from a zip bundle or a folder of YAML files (the `local` block), or
- **on a seristack HTTP server**, behind your own authentication (the `http` block).

It supports:

- resources (`opsy_seristack`)
- data sources (`opsy_seristack`)
- ephemeral resources (`opsy_seristack`)
- actions (`opsy_seristack`)
- provider-defined functions

Set at most one of the `local` and `http` blocks. With neither, only the provider-defined functions are available.

## Example Usage

To use the Opsy provider, declare it as a `required_provider` in the `terraform {}` block:

```terraform
terraform {
  required_providers {
    opsy = {
      source = "TechXploreLabs/opsy"
    }
  }
}
```

### Local mode

Each resource `type` maps to `<type>.yaml` (or `.yml`) inside the configured zip bundle or folder.

```terraform
provider "opsy" {
  local {
    path = "${path.module}/archive.zip"
    # or a directory of YAML files:
    # folder_path = "${path.module}/stacks"
  }
}
```

### HTTP mode

Each stack is called on the server as `<url>/<type>_<STACK>`. `GET` and `DELETE` send variables in the query string; `POST` and `PUT` send them as a JSON body.

Authentication is done by a *provider stack*: a stack in a local YAML file that runs on your machine and prints JSON. The keys listed in `output` are sent on every request. The key `access_token` is sent as `Authorization: Bearer <value>`.

```terraform
provider "opsy" {
  http {
    url                 = "https://seristack.example.com/oci/"
    provider_stack_file = "${path.module}/auth.yaml"
    provider_stack_name = "auth0"
    vars = {
      token_url     = "https://example.auth0.com/oauth/token"
      client_id     = var.client_id
      client_secret = var.client_secret
      audience      = "https://api.example.com"
    }
    output = ["access_token"]
  }
}
```

## Function Syntax

As of Terraform 1.8 and later, providers can implement functions that you can call from the Terraform configuration.

You use the functions with a special syntax: `provider::opsy::<function_name>`.

### Nested Schema for `http`

Optional:

- `output` (List of String) Keys of the provider stack's JSON output to send on every request. The key `access_token` is sent as `Authorization: Bearer <value>`; any other key is sent as an HTTP header with that name. An optional `expires_in` key (seconds) in the JSON tells the provider when to run the stack again.
- `provider_stack_file` (String) Path to a local YAML file that contains the provider stack. Required together with `provider_stack_name` and `output`.
- `provider_stack_name` (String) Name of the stack in `provider_stack_file`. It runs on this machine (not on the server) the first time credentials are needed, and again when they expire or the server answers 401.
- `url` (String) Base URL of the seristack server, for example `https://seristack.example.com/`. Required when the `http` block is present.
- `vars` (Map of String, Sensitive) Variables passed to the provider stack (for example `token_url`, `client_id`, `client_secret`, `audience`). Declare each one under `vars:` in the stack. Two keys are also read by the provider itself: `ca_cert_file` (PEM bundle to trust) and `timeout` (per-request Go duration, default `2m`).
