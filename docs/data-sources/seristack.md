# opsy_seristack (Data Source)

Reads data by executing the `DATASOURCE` stack from a seristack type definition. Stacks run either locally (provider `local` block) or on a seristack HTTP server (provider `http` block).

The `type` value selects the stack definition:

- **local mode:** it maps to `<type>.yaml` (or `.yml`) inside the configured bundle (archive.zip) or folder. For example, `type = "oci_bucket"` resolves `oci_bucket.yaml`.
- **http mode:** the call is `GET <url>/<type>_DATASOURCE`.

A `DATASOURCE` stack only reads: it must not change anything. It prints `{"id": "...", "output": {...}}`.

To know more about seristack, please visit [seristack](https://seristack.getsaas.in/).

## Example Usage

```bash
mkdir opsyyamls
cd opsyyamls
touch oci_bucket.yaml
```
add the below content in the yaml file

```yaml
stacks:
- name: DATASOURCE
  count: 1
  vars:
  - name: namespace
    allowed_value: ["bm0fmmqpaonp"] 
  - name: name
    allowed_regex: regex("^[a-zA-Z0-9._-]{1,256}$")
  - name: region
    allowed_value: ["ap-mumbai-1"]
  cmds:
  - |
    # unset OCI_CLI_AUTH
    # CONFIG="--config-file <update config file path> --profile DEFAULT"

    cmd=(oci $CONFIG os bucket get --region {{.Vars.region}} --namespace {{.Vars.namespace}} --name {{.Vars.name}})
    bucket_json="$("${cmd[@]}")" || exit 1

    jq -n \
      --arg id "{{.Vars.namespace}}/{{.Vars.name}}" \
      --argjson data_result "$bucket_json" \
      '{id: $id, output: {bucket: $data_result.data}}'
```

```terraform
terraform {
  required_providers {
    opsy = {
      source = "TechXploreLabs/opsy"
    }
  }
}

provider "opsy" {
  local {
    folder_path = "${path.module}/opsyyamls"
  }
}

data "opsy_seristack" "bucket" {
  type = "oci_bucket"
  vars = {
    namespace = "namespacename"
    name      = "bucket-name"
  }
}

output "bucket_data" {
  value = data.opsy_seristack.bucket.output
}
```
