# opsy_seristack (Action)

Runs a named stack from a seristack type definition. Stacks run either locally (provider `local` block) or on a seristack HTTP server (provider `http` block).

The `type` value selects the stack definition:

- **local mode:** it maps to `<type>.yaml` (or `.yml`) inside the configured bundle (archive.zip) or folder, and `stackname` is the name of a stack in that file. For example, `type = "function"` and `stackname = "function_1"` run the stack `function_1` from `function.yaml`.
- **http mode:** the call is `POST <url>/<type>_<stackname>`, with the variables in a JSON body. The stack must be registered on the server with `method: POST`.

Actions are invoked on demand, for example to restart a service, run a backup or flush a cache.

To know more about seristack, please visit [seristack](https://seristack.getsaas.in/).

## Example Usage

```bash
mkdir opsyyamls
cd opsyyamls
touch function.yaml
```
add the below content in the yaml file

```yaml
stacks:
- name: ACTION
  count: 1
  vars:
  - name: name
    value: "null"
    allowed_value: ["opsy"]
  cmds:
  - |
    echo "{{.Vars.name}}"
```

```terraform
terraform {
  required_providers {
    opsy = {
      source = "TechXploreLabs/opsy"
    }
  }
}

provider "opsy" {
  local {
    folder_path = "${path.module}/opsyyamls"
  }
}

action "opsy_seristack" "run_function" {
  config {
    type      = "function"
    stackname = "function_1"
    vars = {
      name = "opsy"
    }
    timeout = "20m" # optional, default 30m
  }
}
```

```bash
terraform apply -invoke=action.opsy_seristack.run_function
```

## Long-running stacks

If the stack answers `seristack_status = pending`, the provider waits `seristack_retry` and calls the **same stack again** (with `seristack_status=pending`, `id` and `seristack_status_vars`) until the stack reports `succeeded` or `failed`, or until `timeout` is reached. Terraform shows progress messages while it waits. A stack that does not use this protocol simply runs once.

Every action stack receives the variable `seristack_status` (`null` on the first call), so it should declare it. See the [`opsy_seristack` resource](../resources/seristack.md#long-running-operations) for the full contract.

Variable names starting with `seristack_` are reserved. Setting one in `vars` fails when the action runs.

## Schema

### Required

- `stackname` (String) Stack name to be executed. Over http the stack must be registered on the server with `method: POST`.
- `type` (String) Resource type name. Maps to `<type>.yaml` (local) or the endpoint prefix (http).

### Optional

- `timeout` (String) Go duration limiting the whole run, status checks included, for example `45m`. Default `30m`. If the stack answers `seristack_status = pending`, the provider calls it again after `seristack_retry` until it reports `succeeded` or `failed`.
- `vars` (Map of String) Variables to pass to the stack. Names starting with `seristack_` are reserved.
