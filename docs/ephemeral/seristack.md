# opsy_seristack (Ephemeral Resource)

Runs the `OPEN` stack of a seristack type and returns its output. Nothing is stored in state or plan files, so this is the right way to fetch a secret (a password, a token, a key) and hand it to a [write-only attribute](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) such as the `sensitive` map of the `opsy_seristack` resource.

Requires Terraform 1.10 or later.

The `type` value selects the stack definition:

- **local mode:** it maps to `<type>.yaml` (or `.yml`) inside the configured bundle (archive.zip) or folder. For example, `type = "oci_vault_secret"` resolves `oci_vault_secret.yaml`, which must define an `OPEN` stack.
- **http mode:** the call is `POST <url>/<type>_OPEN`, with the variables in a JSON body.

The `OPEN` stack prints one JSON object whose `output` value becomes the `output` attribute:

```json
{"output": {"value": "the-secret", "version-number": 3}}
```

`OPEN` is always a single synchronous call. It is never polled, so it does not use `seristack_status`.

To know more about seristack, please visit [seristack](https://seristack.getsaas.in/).

## Example Usage

```terraform
terraform {
  required_providers {
    opsy = {
      source = "TechXploreLabs/opsy"
    }
  }
}

provider "opsy" {
  local {
    folder_path = "${path.module}/opsyyamls"
  }
}

# Fetch the secret at plan/apply time. It is never written to state or plan files.
ephemeral "opsy_seristack" "db_password" {
  type = "oci_vault_secret"
  vars = {
    secret_id = "ocid1.vaultsecret..."
    region    = "ap-mumbai-1"
  }
}

# Pass it to a write-only attribute.
resource "opsy_seristack" "database" {
  type = "my_database"
  vars = {
    name = "orders"
  }
  sensitive = {
    password = ephemeral.opsy_seristack.db_password.output.value
  }
}
```

## Schema

### Required

- `type` (String) Type name. Maps to `<type>.yaml` (local) or the endpoint prefix (http). It must define an `OPEN` stack.

### Optional

- `sensitive` (Map of String, Sensitive) Sensitive variables (tokens, passwords, keys), merged on top of `vars`.
- `vars` (Map of String) Variables passed to the `OPEN` stack. Values must be strings; use `jsonencode()` for lists and objects.

### Read-Only

- `output` (Dynamic, Sensitive) The `output` object printed by the `OPEN` stack.
